# E3-A2: elementos y vistas C4 reutilizables

Base aceptada: E3-A1 `6dfd817`, sobre E1/E2. Decisiones de formato y recuperación: [ADR 0013](../adr/0013-c4-native-views.md). Se conserva el envelope E0-A y se añaden propiedades namespaced, tipos incorporados y validación de familia.

## Subconjunto implementado

| Vista | Ámbito y elementos C4 admitidos |
|---|---|
| `context` | Sistema focal requerido; personas, sistemas y límites. |
| `containers` | Sistema focal requerido; sus contenedores (con límites intermedios), personas, sistemas y límites. |
| `components` | Contenedor focal requerido; sus componentes, personas, sistemas, contenedores y límites. |
| `deployment` | Entorno explícito; nodos de despliegue e instancias de ese entorno. Sistema focal opcional limita las instancias a ese sistema o sus contenedores. |
| `dynamic` | Proyecto, sistema o contenedor; personas, sistemas, contenedores, componentes y límites. Los pasos referencian RelationViews locales y tienen identidad y orden explícitos. |

Las vistas se crean vacías para poder construirlas progresivamente. Una inserción C4 incompatible con su familia se rechaza sin escribir. Los nodos de contenido/anotaciones del workspace mantienen su semántica propia. Las categorías, jerarquía, relaciones y pasos se validan en el dominio puro; React Flow es una proyección.

El inspector permite crear elementos, editar propiedades, elegir padre semántico e instancia base, crear relaciones, reutilizar elementos/relaciones y crear/navegar vistas. Los controles de secuencia añaden, reordenan y quitan pasos. Cada representación conserva posición/tamaño/estilo propios; cambiar título o propiedades de una entidad se refleja en las demás vistas. Duplicación de contenido remapea referencias internas de padre/instancia y conserva las referencias externas. Los campos desconocidos se mantienen al editar.

Los renderers incorporados usan tarjetas C4 y relaciones diferenciadas. Los límites son entidades con referencias semánticas y una tarjeta identificada; no se convierten en grupos visuales ni organizan automáticamente posiciones. No se interpreta Markdown como HTML ni se abre/descarga la URL de un elemento al cargarlo.

## Criterios y pruebas

Fixture compartido: [scenario.json](../../fixtures/e3/c4/scenario.json), con los siete tipos, un tipo personalizado explícitamente mapeado, sistema/contenedor/componente, límites, dos niveles de despliegue, instancias y cinco vistas.

| Criterio | Evidencia de este bloque | Cobertura pendiente |
|---|---|---|
| A3-012 | Reutiliza el mismo sistema y relaciones entre vistas; conserva jerarquía, referencias y pasos tras cerrar/reabrir mediante el store Windows. | Parcial: exportar con fidelidad a otro formato/motor requiere E3-E/E3-F. |
| A3-004 / A3-006 | Modelo compartido, posiciones independientes, separación de grupos y contención; integración en el lienzo e historial común para ediciones. | No se vuelve a declarar completa toda la aceptación de canvas. |
| A3-005 | Duplicar contenido remapea padres internos incluso si la selección enumera al hijo antes que al padre. | No se añaden nuevos modos de duplicación. |
| A3-033 / A3-047 | Comandos revisados y broker del host; pruebas de revisión obsoleta y revocación de `diagram.edit` sin cambios en bytes. | Sin nuevos caminos de agente ni permisos de proceso. |
| A3-042 | Falta el paquete personalizado: conserva entidad, propiedades y RelationViews y usa fallback. | Instalación/creación de paquetes comunitarios corresponde a E6. |
| A3-046 | Fallos inyectados al crear workspace/vista tras intención, staging, primera instalación y antes de confirmar; recuperación repetida y preservación de contenido externo en la carpeta nueva. | No se probó corte eléctrico físico ni se declara atomicidad global entre archivos. |
| A3-052 | Formularios etiquetados y botones para navegar/ordenar sin gestos de arrastre obligatorios. | Sin auditoría completa de accesibilidad o escala. |

Comprobaciones reproducibles:

- `npm test`: contratos E0, dominio, store, coordenadas de canvas y lenguajes existentes, incluyendo los tests C4 nuevos.
- `npm run build`: dominio/store, tipos main/renderer y build Electron/Vite.
- `npm run test:c4 --workspace @a3/desktop`: smoke Electron aislado, inspector, jerarquía, navegación, reutilización de IDs, relaciones separadas de VisualEdge y secuencia repetida/reordenable.
- `npm run test:conceptual --workspace @a3/desktop`: regresión del inspector conceptual y render común.

Resultado local observado (Windows, 2026-10-16): suite general 279/279; después del último guard de proyección, prueba aislada de binding 1/1 y build completo aprobados. Los smokes Electron C4 y conceptual también aprobaron. El binding mutuo workspace/documento impide elegir arbitrariamente entre documentos de vista conflictivos; no se interpreta como vista editable una versión no soportada.

## Límites

Este bloque implementa modelos y vistas nativas. No ejecuta Structurizr/Java ni instala motores o dependencias nuevas; no implementa importación DSL/JSON, SVG/PNG/PDF, relaciones implícitas, secuencias paralelas, landscape ni infraestructura adicional. La matriz de §14.2 se mantiene para sus adaptadores posteriores; disponer de las primitivas no acredita conversión ni fidelidad de exportación. Los pins y el lockfile permanecen sin actualizaciones.
