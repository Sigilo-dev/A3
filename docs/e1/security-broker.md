# E1-E1: broker de capacidades por proyecto

Relaciona los criterios A3-031, A3-032 y A3-033. Las operaciones que entran por `ProjectService` consultan el broker del host para abrir un proyecto, leer recursos, preparar escrituras y aplicarlas. El kernel de dominio recibe la decisión estructurada del host y continúa siendo independiente del sistema de archivos. `StoreHost` ya no acepta callbacks permisivos de autorización.

Las capacidades tienen identificadores estables: `project.read`, `mount.read`, `mount.write`, `document.edit`, `diagram.edit`, `task.edit`, `delete`, `project.recover`, `process.run`, `network.access`, `package.install`, `git.status`, `git.diff`, `git.stage`, `git.commit`, `git.push`, `git.branch`, `git.restore` y `export`. La edición de entidades y documentos usa `document.edit`; workspaces, placements, relaciones, líneas, grupos y dibujos usan `diagram.edit`; colecciones de tareas usan `task.edit`; borrar requiere `delete` además de la capacidad de edición del elemento. Un journal pendiente requiere `project.recover` y las capacidades registradas al preparar la operación. Registrar tipos de nodo requiere `package.install`. Las capacidades sin una operación implementada permanecen denegadas.

Los perfiles son `consultar`, `proponer`, `trabajar` y `personalizado`. Consultar solo concede lectura del proyecto. Proponer, el perfil inicial recomendado, concede lectura y permite preparar ediciones documentales, de diagramas y tareas; cada aplicación requiere confirmación del host para esa operación. Trabajar aplica directamente esas ediciones. Ningún perfil concede por sí mismo eliminación, procesos, red, paquetes, Git o exportación. La recuperación de journals pendientes requiere confirmación incluso en Trabajar. Personalizado comienza con denegación y requiere concesiones individuales.

El documento compartible `.a3/policies.json` se puede interpretar con `parseSharedPolicyRequest`, que solo devuelve solicitudes declarativas. El broker no lee ese archivo para decidir permisos. Las concesiones efectivas se guardan en el directorio local del host bajo `project-capabilities`, ligadas al hash de la ruta canónica del proyecto y su UUID; se validan en cada operación. El host obtiene el UUID del manifiesto seleccionado y exige esa concesión exacta antes de catalogar el resto del proyecto. `setProfile` usa Proponer si no se indica perfil. Cambiar perfil, conceder o revocar requiere la callback de confirmación humana del proceso principal. Revocar modifica el registro local y afecta a la siguiente comprobación. Un clon en otra ruta no encuentra esa concesión.

Las decisiones permitidas y denegadas se añaden a `capability-audit.ndjson`, fuera del proyecto. Cada fila registra hora, clave opaca del proyecto, tipo de actor, operación, capacidad y resultado; no guarda rutas, prompts, bytes, tokens ni contenido. Si el registro de auditoría no está disponible, la operación falla cerrada. No se promete que el archivo sea resistente a manipulación local.

E0-C2 verificó que los comandos de proceso pueden escapar una guarda lógica mediante rutas relativas y junctions, y no demostró aislamiento de proceso ni red. Por ello `mount.write`, `process.run`, `network.access`, `package.install`, todas las acciones Git y `export` responden `capability-unavailable` incluso si una política local solicita una concesión. No se ejecutan comandos arbitrarios en E1-E1/E2. `mount.read` solo funciona mediante el lector acotado E1-E2 y requiere tanto esa capacidad como una carpeta aprobada localmente para el proyecto. URLs remotas siguen denegadas.

La superficie actual cubre el servicio de proyecto del proceso principal. La UI de permisos, los canales IPC de la app, agentes externos, la pestaña de ChatGPT, extensiones y plugins aún no están conectados a este servicio; no deben recibir referencias al broker ni a los permisos locales. Tampoco quedan cubiertos cambios hechos directamente por otros programas en el sistema de archivos: el watcher del escritor los reporta como conflictos, pero no los puede impedir. Antes de habilitar procesos, red, paquetes o adaptadores Git/exportación se requieren controles y pruebas propios para esas capacidades, incluyendo aislamiento del sistema operativo cuando aplique.
