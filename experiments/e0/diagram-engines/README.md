# E0-D2 diagram engine spike

This spike contains only synthetic fixtures and version-pinned adapters. It is not an A3 application module or a production dependency recommendation. Node.js 24.13.1 and Eclipse Temurin Java 21.0.10 were present on the host. The spike did not install any runtime globally.

From this directory, run `npm ci`, then `npm run mermaid:ast`. Start the Mermaid page with `npm run mermaid:serve`, open `http://127.0.0.1:4173`, and press **Parse and render both fixtures**. It saves the generated SVG files under `outputs/mermaid/` and checks the checked-in fixture hashes before writing.

Run `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-plantuml.ps1` to verify the pinned MIT JAR and write SVG/PNG outputs. Run `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-structurizr.ps1` to validate DSL and JSON and export local views. The Structurizr export script sets `PLAYWRIGHT_BROWSERS_PATH` to the ignored `.cache/playwright/` directory before invoking its Playwright-backed renderer. The first run can download browser binaries there; no browser is downloaded to the user-wide cache by this script.

For the Structurizr local UI, copy either `fixtures/structurizr/workspace.dsl` or `fixtures/structurizr/workspace.json` into a fresh directory under `.cache/`, then run `java -Dserver.address=127.0.0.1 -Dserver.port=4180 -jar .cache/structurizr-2026.09.19-playwright.war local <that-directory>`. Open `http://127.0.0.1:4180`. Stop the Java process after the check. Use only the synthetic fixtures; the UI is editable and writes workspace changes into its data directory.

Downloaded JAR/WAR files and local browser runtimes are ignored under `.cache/`. Their pinned official URLs and SHA-256 values are in `binaries.lock.json`. Generated outputs are checked in as evidence and can be regenerated by these scripts.
